# 界面设计（打轴页）

改版式之前先读这份；改完回来补「变更记录」。
**结构、层级、规矩**记在这里，具体像素以 CSS 为准（对不上时以 CSS 为真，并回来修这份）。

## 1. 三屏骨架

| 屏 | `id` | 职责（一句话） | 编排文件 |
|---|---|---|---|
| 载入 | `#setup` | 凑齐三样东西：音频、歌词、存档名 | `screen/setup.js` |
| 打轴 | `#tapping` | 看着音频改字的时间 | `screen/tapping.js` |
| 校验 | `#review` | 逐句回听、单字微调、交付 | `screen/review.js` |

屏切换靠 `core/screen.js`（`register / show / key / tick`），屏契约是
`{ id, el, activate, deactivate?, tick?, onKey? }`。**不要**在屏里直接操作别的屏。

## 2. 打轴屏：一条竖线按「看音频 → 改字 → 确认」排序

```
┌─ header        ← 返回 · 曲名 · 当前秒数 ─────────────┐
├─ .wavebox (86) 整段音频波形 + 打点竖线 + 放大区间底色 ┤
├─ .tap-body ────────────────────────────────────────┐ │
│  .tap-main                        │  .rail (292)   │ │
│   #tl      时间轴（一字一框，92）  │  捕获面板       │ │
│   .stage   大字歌词（30–58px）     │  逐字 t / dt /  │ │
│   .hud     第 x/y 句 · 已打 x/y 字 │  时长条 / 异常  │ │
│   .tip     一句操作反馈（橙色）    │                │ │
│   .grow    弹性空白               │                │ │
│   .keys    键位条（固定在底部）    │                │ │
└───────────────────────────────────┴────────────────┘
```

**为什么是这个顺序（每一条都是踩过坑定的）**

| 位置 | 理由 |
|---|---|
| 波形在最上 | 它是唯一的时间基准，所有判断都以它为准 |
| 时间轴紧贴波形（0 间距） | 两处共用 x 轴的语义，必须挨着看。**曾经把大字设成 `flex:1` 居中，把时间轴挤到屏幕最底部，被判定为「音频和字分家」** |
| 大字在轴下面 | 跟唱时眼睛主要在字上，轴只是参照 |
| hud / tip 紧跟大字 | 反馈要贴着操作，不能飘到屏幕底部 |
| 键位条最底 | 它是「学习区」，不需要一直看；固定在底部反而建立肌肉记忆 |
| 捕获面板放右侧 | 不遮挡字、可常驻；固定 292px，窄于 900px 自动收起（`@media`） |

> 改布局前先问一句：**这块信息是「看音频时同时要看的」还是「看完再看」的？**
> 前者必须贴着波形，后者往下放。

## 3. 页面上有两条 x 轴，刻度不一样（最容易误解）

| | 波形 | 时间轴 |
|---|---|---|
| 覆盖范围 | 整段音频 0 → `state.dur` | **只有当前这一句** |
| 1px 约等于 | 25–50ms（看音频多长） | 2–5ms |
| 相对放大 | 1× | **约 10–25×** |
| 上面的点 | 每个打点的真实 `t` | 每个字的 `[t, e]` 区间 |

所以同一个字在两个地方的位置**不会对齐**，这是设计不是 bug。
为了让人不误解，做了三件事：

1. 波形上给当前句画**浅色底 + 左右两条边线**（`paintWave` 的 `focus`）
2. 打点竖线在同一位置 2px 内**只画一根**，放大区间外的画淡（22% 不透明度）
3. 时间轴的播放头 1px / 55% 透明，和波形上那根 2px 亮橙区分开

> 如果哪天又有人说「怎么一堆橙色竖线糊在一起」，先确认他是不是把
> 「放大后的 5 个字」当成了「整首歌的前 5 个字」。

## 4. 时间轴（本工具的核心交互）

### 4.1 为什么相邻两个字一上一下

相邻两个字如果同排，`分`的右边和`手`的左边会落在同一个 x 点上，
两条抓取带互相压住，鼠标永远点不准。一上一下之后，两条边在垂直方向分开。

上排 `top: 4px`，下排 `top: 50px`，框高 34px。

### 4.2 颜色：相邻交替，靠色相不靠明度

| 序号 | 边框 | 用途 |
|---|---|---|
| 偶数 | `#35c08f` 青绿 | 和 `--ok` 同一族，深色底上够亮 |
| 奇数 | `#e0a53a` 琥珀 | 和 `--acc` 同族但更黄，和青绿对比最强 |

不用「同色相深浅」交替：深色底上明度差在小尺寸里几乎看不出，色相差一眼就分得开。

### 4.3 尺寸与命中区

| 元素 | 值 | 理由 |
|---|---|---|
| 框高 | 34px | 能放 16px 字，两排 + 间距 ≈ 92px 总高 |
| 框最小宽 | 18px | 再窄就点不中，宁可视觉重叠 |
| 边框 | 1.5px | 1px 在深色底上发虚 |
| 抓取带 | 宽 11px、横向探出框外 6px、上下各多 3px | **命中区是视觉线的近 4 倍**（视觉线只有 3px），按住不发抖 |
| 圆角 | 7px | 和按钮的 8px 同一族 |

### 4.4 两种状态：草案 vs 落定

- **虚线 + 70% 透明** = 均分草案，**没有写进 state**，一拖就没了
- **实线** = 这个字有真实 `t`

第一次拖任何一条边 → `fillLineEven()` 把整句落成真实值。
**「不拖就不写」是刻意的**：让「跟唱打点」和「拖时间轴」两种打法能混着用，互不污染。

### 4.5 选中态三级（视觉上必须一眼分辨）

| 状态 | 画法 | 含义 |
|---|---|---|
| 未选 | 只有 26% 透明的两条抓取条 | 可拖 |
| `.sel` | 整块 **2px 白色外环**（`outline` + `outline-offset:2px`）+ 文字纯白 | 「你选的是我这个字」，`←/→` 默认调起点 |
| `.sel-l` / `.sel-r` | 白环 + 指定那条边压 **5px 白竖条** | 「你调的是这条边」 |

用 `outline` 而不是 `box-shadow`：`box-shadow` 已经被 `.cur`（当前待打）和 `.hot`（拖动中）占用，
叠加会互相覆盖。

### 4.6 鼠标给大概，键盘给精确

| 手段 | 精度 | 用途 |
|---|---|---|
| 拖 | ±10~30ms（看缩放） | 定位，不求准 |
| `←` `→` | **1 帧** = 33ms | 精调 |
| `Shift` + `←` `→` | **10 帧** = 333ms | 快移 |

**不要在鼠标里做精细微调**：200px/s 的缩放下 1 帧只有 6px，手一定抖过头。
所以交互必须允许「拖完不松手也不重新点，直接按键」——这就是选中态要独立于拖动存在的原因。

### 4.7 边界约束（夹取全在 `core/lines.js`）

```
t_i >= e_{i-1}          起点不能越过上一个字的终点
e_i <= t_{i+1}          终点不能越过下一个字的起点   ← 空隙就是这么拖出来的
e_i >= t_i + 0.08s      最短 0.08s（约 2.4 帧）
```

视图层只负责把指针位置换算成秒（并吸附到帧），**不判断合法性**。

## 5. 右侧「捕获」面板

四块，从上到下：

1. **头部**：`捕获` + 本句是否已收句（`+1.55s` 绿色 / `未收句` 灰）
2. **摘要**：`第 1/2 句 · 已打 6/11 字`
3. **逐字列表**：`字 | 起点 t | 与上一字的间隔 dt | 底部时长条`
   - `dt > 1.2s` 黄（长间隙）、`> 2.5s` 红（多半漏打了一个字）、`< 0.1s` 橙（太快）
4. **底部汇总**：`长间隙 N` / `太快 N` / `节奏正常`

存在的理由：波形上那几个竖条看不出「这个字亮多久」，打完一段心里没底。

> 实现细节：`renderRail` 用一个 `sig` 字符串比对，内容没变就跳过重建（每帧都会调用）；
> 行内的 `.durbar` **不能**叫 `.bar` —— 会和 `base.css` 里的顶栏 `.bar` 撞类名（踩过）。

## 6. 键盘总表

| 键 | 打轴屏 | 校验屏 |
|---|---|---|
| `空格` | 播放 / 暂停 | 播放 / 暂停 |
| `F` | **打点**（记起点） | — |
| `Enter` | 收句（记本句真实结束） | 播当前句 |
| `Ctrl+Enter` | 跳过本句剩余字 | — |
| `Backspace` | 退一个点（并回退重播） | — |
| `Shift+Backspace` | 整句重来 | — |
| `←` `→` | 有选中边 → 调那条边；否则挪播放头 | 有选中字 → 微调；否则切句 |
| `Shift+←` `→` | ×10 帧 | ×10 帧 |
| `↑` `↓` | 换句（只动时间轴视图） | 切句 |
| `R` | 本句重来（等价于 Shift+Backspace） | — |
| `Esc` | 回载入屏 | 回打轴屏 |

规则：**只有方向键吃长按**（`core/keys.js`），其余键 `e.repeat` 一律丢弃，
否则空格会连切播放/暂停、F 会连打。

## 9. 红线

1. **视图层不写时间算法**。`view/` 里只做换算（pixel ↔ second），夹取一律回 `core/lines.js`。
2. **不新增颜色字面量**，除了上面第 7 节点名的三处。
3. **微调一律按帧**（`core/time.js` 的 `FRAME`）。0.01s 在 30fps 成片里是假精度。
4. **任何自动写 state 的行为必须由用户动作触发**（不拖不写、不点不写）。
5. **波形 / 时间轴 / 大字** 的垂直顺序不许乱（见第 2 节的判定标准）。
6. 单个屏文件超 **250 行**就拆：画推 `view/`、算推 `core/`、存推 `export/`。
